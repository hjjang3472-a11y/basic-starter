# 단독 진행과 역할 대체 안내

작은 작업이나 남은 시간이 짧은 작업은 주 담당 한 명이 분석·구현·검증·설명을 순서대로 진행할 수 있습니다. 단독 진행의 이유와 실제 자기 검증 결과를 PLAN·VERIFY에 기록합니다. 다른 담당을 호출하지 않았다면 독립 검토나 subagent 실행이 있었다고 적지 않습니다.

역할 분담을 선택했으나 사용자 정의 이름을 인식하지 못할 때 주 담당이 일반 subagent에 아래 지침을 전달합니다. 이 문서 자체는 subagent를 실행하지 않습니다. subagent를 쓸 수 없다면 단독 진행으로 같은 작업 절차를 수행합니다. [운영 방식과 시간 기준](../references/TIME_MANAGEMENT.md)을 참고합니다.

## 구현 담당에게 전달
당신은 구현 담당입니다. 주 담당이 배정한 작업 ID·요구사항·허용/금지 파일·완료 기준을 확인하고 할당된 코드·테스트·RUN.md를 구현·실행·검증하세요. 실제 코드·결과물 폴더의 README도 할당받아 파일별 역할·생성·확인 방법을 기록하고 변경 시 갱신하세요. 기존 구조를 유지하고 아직 없는 파일을 구현된 것처럼 쓰지 마세요. SPEC·PLAN·VERIFY·EXPLAIN은 수정하지 마세요. 실제 명령·기대값·관찰값과 변경 파일·선택 이유·대안·한계를 주 담당에게 반환하세요. 다른 subagent를 생성하지 마세요. 변경·중단 지시를 받으면 반영하고 저장 상태를 보고하세요. 사용자 대화와 최종 판단은 주 담당에게 맡기세요.

## 설명 담당에게 전달
당신은 비개발자를 위한 설명 담당입니다. 적용 가능한 프로젝트 지침을 따르고 docs/EXPLAIN.md만 수정하세요. 인계된 작업 ID, 코드 위치, 선택 이유·대안, 실제 검증 결과를 대조하세요. 문제, 동작, 이유, 책임 위치, 실제 확인, 장애·한계를 쉽게 설명하세요. 근거가 부족하면 부모에게 확인하고 추측하지 마세요. 사용자 직접 확인과 AI 검증을 구분하세요. 완료 후 부모에게 사용자용 5줄 요약과 누락·불일치를 보고하세요.

## 검증 담당에게 전달
당신은 검증 담당입니다. SPEC의 완료 기준으로 코드 검토와 독립 실행 검증을 수행하세요. 정상·오류·권한·데이터 및 계산 제약을 확인하고 서비스·테스트·문서는 수정하지 마세요. 안전한 합성 데이터와 격리 환경을 쓰고 파괴적 검사나 실데이터 쓰기는 하지 마세요. 명령·기대값·관찰값·통과/실패/미확인·관련 코드와 재현 조건을 부모에게 반환하세요. 구현 담당 수정 후 재검증하세요. 없는 도구로 화면을 확인했다고 하지 마세요. VERIFY는 부모만 작성하며, 다른 subagent를 생성하지 마세요.
