# 기존 프로젝트에 적용하는 시작 요청

나는 비개발자입니다. 이 요청문이 들어 있는 Basic Starter 저장소를 참고해 현재 프로젝트에 작업 방식을 적용하고, 요구사항 분석부터 진행해 주세요. 템플릿 저장소와 실제 작업 대상 프로젝트를 구분하세요. 대상 경로가 불명확하면 확인하고, 템플릿 폴더를 실제 프로젝트로 잘못 변경하지 마세요.

1. 현재 프로젝트의 README·기존 지침·코드·설정·제공 데이터·실행 방법·제출 문서를 먼저 확인하세요. 원본과 기존 구조를 보존하세요. Basic Starter의 README, AGENTS.md, .codex/agents에 있는 역할 정의도 읽으세요. AGENTS.practice.md가 있으면 함께 읽으세요.
2. 기존 프로젝트에 맞게 필요한 지침·에이전트 정의·기록 양식과 .agents/skills의 문서형 스킬을 적용하세요. 기존 스킬은 덮어쓰지 말고 차이를 확인하세요. 기존 AGENTS.md를 통째로 교체하지 말고 적용 가능한 내용을 통합하며 충돌은 명시하세요. 같은 역할의 문서가 있으면 우선 활용하고 역할 정의에도 실제 문서 경로를 반영하세요. HOW_TO_RUN.md나 AI 협업 기록 양식이 있다면 확인하세요. RUN.md에는 검증한 실행 정보를 남기고 기존 제출 문서와 일치시키세요. 없는 제출 양식을 임의로 추가하지 마세요. 별도 설치 프로그램은 필수가 아니며 파일 복사 도구 사용 여부는 상황에 맞게 정하세요.
3. 적용한 지침과 역할, 실제 문서 위치, 스킬 인식·subagent 사용 가능 여부를 확인해 알려 주세요. 파일이 있다는 이유로 역할이 인식되거나 실행됐다고 단정하지 마세요. 이어서 프로젝트 목표, 필수 조건, 불확실한 가정, 구현·검증 계획을 쉬운 말로 설명하세요. 만들 대상이 정해지지 않았다면 사용자에게 목표를 확인하세요.
4. 주 담당은 나와의 대화, 요구사항·계획, 결과 취합과 최종 판단을 맡으세요. 작업 규모·남은 시간·도구 지원·인계와 통합 비용을 보고 단독 진행 / 역할을 나눠 진행 / 독립 작업 병렬 진행 중 적합한 방식을 선택하고 이유를 PLAN에 남기세요. 작은 작업은 주 담당이 구현·검증·설명을 순서대로 할 수 있습니다. 역할을 나눴다면 implementer의 구현·자체 테스트 후 verifier가 주요 기능을 독립 검증하고, 실패 시 수정·재검증하세요. 실제 근거는 주 담당이 VERIFY에 기록하고 explainer가 EXPLAIN을 갱신하도록 하세요. 단독 검증을 독립 검증으로 적지 마세요.
5. 역할 분담을 선택했으나 사용자 정의 에이전트를 사용할 수 없다면 Basic Starter의 prompts/ROLE_FALLBACK.md를 일반 subagent에 전달하세요. subagent 자체가 불가능하면 주 담당이 같은 절차를 수행하고 차이를 기록하세요. 필요한 단계에서 references/SKILLS.md의 스킬을 사용하고 자동 인식이 안 되면 해당 SKILL.md를 직접 읽으세요. 호환성 확인을 위해 Codex를 업데이트하지 마세요. 실제 마감과 과제 제한을 확인해 응답 대기를 포함한 구현·검증·문서·제출 예산을 PLAN에 남기고 references/TIME_MANAGEMENT.md를 참고하세요.
6. 위임 시 작업 ID·요구사항·수정 허용/금지 파일·완료 기준·검증 방법을 전달하고, 결과에는 변경 파일·함수·선택 이유·대안·실제 검증 명령과 결과·미확인 사항을 받으세요. 같은 파일을 동시에 수정하거나 subagent가 다시 위임하지 않게 하세요.
7. 중요한 작업 전에는 목적을, 완료 후에는 변경·검증·남은 한계·다음 단계를 짧게 설명하세요. 설명 담당의 결과를 주 담당이 확인해 내게 전달하세요.
8. SPEC, PLAN, VERIFY, EXPLAIN 역할의 문서와 RUN.md를 실제 진행에 맞게 갱신하세요. 기존 문서를 활용한 경우 그 대응 관계를 PLAN에 남기세요. 구현 담당은 실제 코드·결과물 폴더의 README에 파일별 역할과 생성·확인 방법을 기록하고 파일 변경 시 갱신하세요. 기존 폴더 이름과 설명을 보존하며 src/나 outputs/ 생성을 강제하지 마세요. 계획에서 멈추지 말고 승인된 범위의 첫 기능을 구현하고 실행·검증하세요.
9. 사용자 판단이 필요한 사항 외에는 매 단계 승인을 기다리지 마세요. 미실행 테스트나 사용자 직접 확인을 수행한 것으로 기록하지 마세요.
10. 작업 중 내가 질문하면 우선 답하고 필요한 변경을 담당에게 전달하세요. 단순 질문을 중단으로 해석하지 마세요. 중단 요청이면 담당에게 전달하고 저장 상태를 확인하세요. 무응답 상시 대기나 반복 조회를 하지 말고 도구 실행 중 메시지 반영 지연과 subagent 미지원 시 단독 수행을 사실대로 알려 주세요. 즉시 응답이나 대화 종료 후 영구 실행을 보장하지 마세요.

첫 사이클 후 내가 설명 시점·길이·난이도에 피드백을 주겠습니다.
