# 첫 대화에 붙여 넣을 요청

나는 비개발자입니다. 이 프로젝트에서 작은 기능 하나를 완성하는 작업 사이클을 진행해 주세요.

1. 현재 프로젝트 README, AGENTS.md, 기존 코드·설정·데이터·실행 방법을 먼저 확인하세요. AGENTS.practice.md가 있으면 함께 읽고 기존 지침과 충돌하는 부분을 알려 주세요. 원문과 기존 구조를 보존하세요.
2. 프로젝트 목표, 필수 조건, 불확실한 가정, 구현·검증 계획을 쉬운 말로 설명하세요. 프로젝트가 없으면 practice/CYCLE_TRIAL.md의 연습을 사용하세요.
3. 주 담당은 나와의 대화, SPEC·PLAN 작성, 업무 배분, 결과 취합, 최종 판단을 맡으세요. 작은 기능의 구현·자체 테스트·실행은 implementer subagent에게 맡기세요. 주요 기능 구현 후 verifier가 SPEC 기준 코드 검토와 독립 실행 검증을 하게 하세요. 실패하면 implementer에게 수정을 맡긴 뒤 verifier가 재검증하게 하세요. 주 담당이 실제 근거를 VERIFY에 기록한 뒤 explainer가 EXPLAIN을 갱신하도록 하세요. 주요 설계 결정도 explainer에게 전달하세요.
4. 사용자 정의 에이전트를 사용할 수 없다면 prompts/ROLE_FALLBACK.md를 일반 subagent에 전달하세요. subagent 자체가 불가능하면 주 담당이 같은 절차를 수행하고 차이를 기록하세요.
5. 위임 시 작업 ID·요구사항·수정 허용/금지 파일·완료 기준·검증 방법을 전달하고, 결과에는 변경 파일·함수·선택 이유·대안·실제 검증 명령과 결과·미확인 사항을 받으세요. 같은 파일을 동시에 수정하거나 subagent가 다시 위임하지 않게 하세요.
6. 중요한 작업 전에는 목적을, 완료 후에는 변경·검증·남은 한계·다음 단계를 짧게 설명하세요. 설명 담당의 결과를 주 담당이 확인해 내게 전달하세요.
7. docs/SPEC.md, PLAN.md, VERIFY.md, EXPLAIN.md와 RUN.md를 실제 진행에 맞게 갱신하세요. 계획에서 멈추지 말고 첫 기능을 구현하고 실행·검증하세요.
8. 사용자 판단이 필요한 사항 외에는 매 단계 승인을 기다리지 마세요. 미실행 테스트나 사용자 직접 확인을 수행한 것으로 기록하지 마세요.
9. 작업 중 내가 질문하면 우선 답하고 필요한 변경을 담당에게 전달하세요. 단순 질문을 중단으로 해석하지 마세요. 중단 요청이면 담당에게 전달하고 저장 상태를 확인하세요. 무응답 상시 대기나 반복 조회를 하지 말고 도구 실행 중 메시지 반영 지연과 subagent 미지원 시 단독 수행을 사실대로 알려 주세요. 즉시 응답이나 대화 종료 후 영구 실행을 보장하지 마세요.

첫 사이클 후 내가 설명 시점·길이·난이도에 피드백을 주겠습니다.
