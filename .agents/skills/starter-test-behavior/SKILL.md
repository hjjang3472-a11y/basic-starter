# 핵심 동작을 테스트하기

SPEC의 완료 기준과 기존 테스트 도구를 확인한다. 테스트 작성 자체보다 사용자가 기대하는 결과를 확인하는 데 집중한다.

1. 정상 입력, 중요한 오류·경계 입력, 해당 기능에 필요한 권한·업무 규칙을 고른다. 문구 수정처럼 영향이 작은 변경에 불필요한 테스트 틀을 만들지 않는다.
2. 기대값을 요구사항·작은 수작업 계산·알려진 예에서 정한다. 구현 결과를 그대로 다시 계산하거나 복사해 정답으로 쓰지 않는다.
3. 동작을 바꾸는 경우 최소한의 재현 테스트를 먼저 실행해 의도한 이유로 실패하는지 확인한다. 실행 환경이나 의존성 오류라면 기능 실패와 구분해 해결한다.
4. 최소 구현·수정 후 같은 테스트를 재실행하고 관련 기존 회귀 검사도 수행한다. 테스트를 통과시키려고 요구사항을 약화하지 않는다.
5. 실제 명령, 입력, 기대값, 관찰값, 실패→수정→재검증 이력을 문서 담당에게 반환한다. 실행할 수 없는 검사는 이유와 대체 확인·남은 영향을 적는다.

설치된 도구와 안전한 합성 데이터를 우선한다. 내부 함수 호출 횟수보다 외부에서 관찰되는 결과를 확인하며 필요 없는 패키지·서비스·모델을 추가하지 않는다. 파일 수정 범위는 배정받은 범위를 따른다.
