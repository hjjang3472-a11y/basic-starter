# 요구사항을 확인하기

기존 README·과제 안내·제공 파일과 SPEC 역할의 문서부터 읽는다. 사용자가 이미 답한 내용은 다시 묻지 않는다.

1. 사용자에게 보이는 목표, 입력과 출력, 필수 조건, 관찰 가능한 완료 기준을 정리한다. 용어가 모호하면 현재 과제의 예로 뜻을 맞춘다.
2. 확인된 요구사항, AI의 제안, 구현을 위해 둔 가정, 아직 확인하지 못한 점을 구분한다. 원문의 위치를 연결하고 전체를 복제하지 않는다.
3. 결과의 정답·범위·데이터 해석을 바꾸는 질문만 먼저 묻는다. 사소한 구현 선택은 합리적인 기본값과 이유를 남기고 진행한다.
4. 기존 SPEC에 반영하고 완료 기준마다 확인 방법을 붙인다. 기능을 임의로 추가하거나 요구사항 정리만 하고 승인된 구현을 멈추지 않는다.

결과는 “만들 것 / 완료라고 볼 조건 / 중요한 가정·질문”을 쉬운 말로 설명한다. 맡은 파일만 수정하며 문서 담당이 따로 있으면 반영할 내용을 인계한다.
