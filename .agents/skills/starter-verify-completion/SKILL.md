# 완료를 말하기 전에 확인하기

완료 주장의 범위를 정하고 그 주장을 확인할 수 있는 검사를 고른다. 과거 통과나 AI의 자신감으로 현재 결과를 대신하지 않는다.

1. SPEC의 해당 완료 기준과 변경 이후의 실제 파일·실행 상태를 확인한다. 관련 검사와 필수 제출 파일·파일명·저장 상태를 확인한다.
2. 중요한 동작의 정상·오류 사례를 실제 실행하고 명령·기대값·관찰값·종료 상태를 확인한다. 검증 담당이 있다면 실제로 수행한 근거를 받는다.
3. 실패하면 완료 주장을 보류하고 원인 수정 후 필요한 검사를 재실행한다. 미실행·환경 제약·확인 범위 밖은 그대로 남긴다.
4. 문서 담당이 VERIFY에 근거를 기록하고 PLAN의 작업·선택과 연결하도록 인계한다. 단독 진행은 자신이 검증했다고 표시한다.
5. 사용자에게 “완료한 것 / 실제 확인한 것 / 남은 한계와 영향”을 짧게 설명한다. 한 검사 통과를 전체 결과의 정상으로 확대하지 않는다.

웹 서비스는 서버 실행, 내부 응답, 미리보기 표시, 핵심 기능 조작을 구분한다. 화면 도구나 접근이 없으면 사용자 직접 확인 전까지 화면은 미확인이다. Git 게시·배포·최종 제출은 각각 허용된 범위에서만 수행하며 이 스킬 자체가 외부 동작을 승인하지 않는다.
