# 원인을 확인한 뒤 수정하기

에러가 난다는 이유만으로 설정을 여러 개 바꾸거나 서버를 반복 실행하지 않는다.

1. 기대 동작, 실제 증상, 발생 시각, 실행 명령·폴더, 오류 로그와 재현 입력을 모은다. 민감값·원본 전체를 로그에 복사하지 않는다.
2. 마지막으로 정상인 단계와 처음 실패하는 단계를 찾는다. 환경·입력·코드 문제를 구분하고 최근 변경과 비교한다.
3. 증거로 설명 가능한 가설 하나를 정하고 가장 작은 확인으로 검증한다. 관찰이 맞지 않으면 가설을 바꾸며 여러 수정을 한꺼번에 섞지 않는다.
4. 원인이 확인되면 배정받은 범위에서 최소 수정하고 같은 재현 조건과 관련 정상 동작을 재검증한다.
5. “증상 / 확인한 원인 또는 아직 가설인 것 / 수정 / 실제 재검증 / 남은 한계”를 반환한다. 실패 시도도 남기며 동일한 실패를 무의미하게 반복하지 않는다.

웹 미리보기 문제라면 프로세스·로그 → 실제 포트 → 수신 주소 → 경로 → 화면·API 요청 순서로 확인한다. 원격 환경이 요구하면 0.0.0.0에 바인딩하고 서버 터미널을 유지한다. 내부 HTTP 성공을 사용자 화면 확인으로 바꾸어 보고하지 않는다. 자세한 절차는 references/TOOLS.md를 따른다.
