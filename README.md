# Basic Starter

요구사항 확인 → 계획 → 구현 → 검증 → 쉬운 설명 → 다음 작업을 반복하는 준비 도구입니다. 주 담당 AI는 사용자 대화와 업무 조율을 맡고, 구현·자체 테스트는 implementer에게, 쉬운 설명 기록은 explainer에게 맡깁니다. 주요 기능이 완성되면 verifier가 코드와 실행 결과를 독립적으로 확인합니다.

비개발자와 개발자가 AI와 함께 계획·구현·검증·설명을 반복하기 위한 기본 템플릿입니다. 기존 프로젝트의 README와 구조를 보존하고 필요한 작업 지침과 문서 양식만 추가합니다.

## 처음 사용하기

1. 이 저장소를 clone하고, 실제 작업할 프로젝트 폴더를 Codex에서 엽니다.
2. 아래 한 문장을 요청하거나 [기존 프로젝트 적용 요청문](prompts/START_CYCLE.md)을 대화에 붙여 넣습니다.
3. 주 담당이 기존 구조를 확인하고 지침·역할·문서를 적용한 뒤, 요구사항 분석과 구현을 진행합니다.
4. AI가 `implementer`, `verifier`, `explainer` subagent를 실제로 호출하는지 확인합니다. 파일 존재만으로 실행된 것은 아닙니다.

> 클론한 basic-starter 저장소의 prompts/START_CYCLE.md를 읽고 현재 프로젝트에 적용해 줘.

다른 위치에 clone했다면 해당 폴더 경로도 알려 줍니다. 시작 요청문은 저장만으로 자동 실행되지 않습니다. 별도 설치 도구를 직접 실행할 필요 없이 주 담당에게 적용을 맡길 수 있습니다. 기존 README·원본 데이터·코드 구조를 보존하고, 같은 역할의 문서가 있으면 활용하도록 안내합니다.

새 프로젝트의 출발점으로 사용할 때는 이 저장소 폴더를 작업 대상으로 열고 만들 서비스를 알려 줍니다. 설명 방식에 대한 의견은 대화로 전달합니다. 템플릿 구조 자체는 `python tools/check_kit.py`로 검사할 수 있습니다.

템플릿 도구는 Python 3.11 이상을 사용하며 별도 패키지는 필요하지 않습니다. 설치 도구의 기존 파일 보존 검사는 `python -m unittest discover -s tests -p "test_*.py" -v`로 실행합니다. 실제 서비스의 실행 정보는 루트 `RUN.md` 한 곳에 기록합니다.

이 저장소에는 문서와 작업 절차, 빈 코드 폴더가 있습니다. 제공 데이터는 실제 프로젝트의 기존 위치를 그대로 사용하며 별도 data 폴더를 추가하지 않습니다. 실행할 서비스와 자동 테스트는 프로젝트를 선택한 뒤 만듭니다. 키트 검사 성공은 서비스 동작이나 subagent 호출 성공을 의미하지 않습니다.

## 선택: 파일 복사 도구로 적용하기

저장소는 기존 프로젝트 폴더 **밖에** clone합니다. 아래의 `/path/to/task`를 실제 프로젝트 폴더로 바꿉니다. Windows에서도 따옴표로 감싼 절대 경로를 사용할 수 있습니다.

```sh
git clone https://github.com/hjjang3472-a11y/basic-starter.git
cd basic-starter
python tools/install_kit.py --target "/path/to/task"
python tools/install_kit.py --target "/path/to/task" --apply
```

첫 설치 명령은 미리보기입니다. `--apply`를 붙여야 파일을 추가합니다. 기존 파일은 덮어쓰지 않습니다. 프로젝트 README·코드·데이터·실행 설정을 복사하거나 교체하지 않습니다.

- 기존 `AGENTS.md`가 없으면 새 지침을 추가합니다.
- 기존 `AGENTS.md`가 있으면 별도 `AGENTS.practice.md`로 추가합니다. 자동으로 읽힌다고 가정하지 말고, 시작 프롬프트에서 읽고 적용 가능한 지침을 통합하도록 요청합니다.
- 기존 문서·에이전트 정의가 있으면 건너뜁니다. 출력의 `EXISTS` 항목은 주 담당이 확인합니다.
- 설치 후에는 **대상 프로젝트 폴더**를 Codex에서 열고, 그곳의 `prompts/START_CYCLE.md`로 시작합니다.

## 역할과 기록

| 담당 | 하는 일 | 파일 담당 |
|---|---|---|
| 주 담당 | 사용자 대화·요구사항·계획·위임·근거 확인·최종 판단 | SPEC·PLAN·VERIFY |
| implementer | 할당된 기능 구현·테스트·실행·검증 증거 보고 | 할당된 코드·테스트·RUN |
| explainer | 근거를 확인하고 쉬운 설명 작성 | docs/EXPLAIN.md |
| verifier | SPEC 기준 코드 검토·독립 실행 검증·재검증 | 서비스·테스트·문서 수정 없이 결과 보고 |

verifier는 주요 기능 구현 후 SPEC의 완료 기준과 실제 동작을 대조합니다. 구현 담당의 자체 테스트에 더해 정상·오류·권한·데이터 및 계산 제약을 확인하고, 실패 시 구현 담당의 수정 후 다시 검증합니다. 검증 근거는 주 담당에게 반환하고 VERIFY는 주 담당만 작성합니다.

설명 담당은 주요 결정, 기능 검증, 중요한 수정, 최종 정리 시 호출합니다. 상시 감시 프로세스가 아닙니다. 같은 파일을 동시에 수정하지 않고, 작업 중인 코드는 변경이 끝난 시점에 검토합니다.

주 담당은 작은 기능 단위를 배정하고 사용자 질문에 우선 답하며 변경 요청을 관련 담당에게 전달합니다. 단순 질문은 작업 중단으로 해석하지 않습니다. 중단 요청은 담당에게 전달하고 저장 상태까지 확인합니다. 구현 담당은 검증 증거를 반환하고 주 담당만 VERIFY를 갱신합니다. subagent의 중첩 위임은 금지하고, 여러 구현 담당은 독립된 파일을 명시적으로 나눌 때만 사용합니다.

이는 작업 역할에 대한 지침입니다. 도구 실행 중에는 메시지 반영이 늦을 수 있으며 즉시 응답이나 대화 종료 후 영구 실행을 보장하는 상시 대기 서버 설정은 아닙니다. subagent 미지원 시 주 담당이 단독 수행하고 실제 방식을 PLAN에 기록합니다.

기록 문서는 네 개로 구분합니다. SPEC은 간단한 PRD 역할도 맡되 기술 구현 계획과 구분합니다.

| 문서 | 답하는 질문 | 기준으로 남기는 내용 |
|---|---|---|
| docs/SPEC.md | 누구에게 무엇이 필요하며 무엇이면 완료인가? | 목표·사용자·기능·업무 규칙·완료 기준·가정 |
| docs/PLAN.md | 어떻게 어떤 순서로 만들 것인가? | 구조·기술·알고리즘 선택·대안·작업 순서·상태 |
| docs/VERIFY.md | 실제로 무엇을 확인했고 결과는 어땠는가? | 검증 명령·기대값·관찰값·오류 수정·재검증 |
| docs/EXPLAIN.md | 사용자가 그 동작과 이유를 이해할 수 있는가? | 쉬운 설명·용어 풀이·근거 문서와 코드 연결 |

프로젝트 README는 원문으로 보존합니다. SPEC에 원문 전체를 복제하지 않고 요구사항 ID와 원문 위치를 연결합니다. PLAN에는 SPEC의 요구사항 ID를, VERIFY에는 검증한 요구사항·작업 ID를 남깁니다. EXPLAIN은 앞선 기록과 코드를 근거로 설명하며 같은 내용을 통째로 복사하지 않습니다.

## 호환성과 도구

`.codex/agents/*.toml`은 프로젝트 범위의 사용자 정의 에이전트입니다. 모델·권한·MCP·개인 인증 설정은 고정하지 않습니다. 설치된 Codex 버전에 따라 사용자 정의 에이전트 인식 여부를 확인해야 합니다. 인식되지 않으면 `prompts/ROLE_FALLBACK.md`의 역할 지침을 일반 subagent에게 전달합니다. subagent 자체를 사용할 수 없으면 주 담당이 설명까지 수행하고 실제 운영 방식을 기록합니다.

별도 MCP·플러그인·Skill 설치는 이 사이클의 필수 조건이 아닙니다. 필요하면 `references/TOOLS.md`에 출처·권한·설치·동작 검증·대안을 기록한 뒤 연결합니다. 이 저장소의 역할 제한은 행동 지침이며 별도 보안 권한을 강제하는 장치가 아닙니다.

## 데이터와 공개 범위

프로젝트에서 허용한 도구·데이터·공개 범위를 따릅니다. 개인정보·비밀키·비공개 코드와 공개 권한이 없는 원본 데이터는 저장소에 올리지 않습니다. 합성 예제 데이터와 실제 프로젝트 데이터를 구분합니다.

이 저장소의 기본 코드·문서는 새로 작성한 범용 준비 자료입니다. 변경 이력은 Git으로 관리합니다.
