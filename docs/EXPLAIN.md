# 쉬운 진행 설명

아직 실제 서비스 작업 사이클을 수행하지 않았습니다. 아래 양식을 주요 작업 단위로 채웁니다.

## 현재 상태
- 완료: 준비 양식 배치
- 미확인: 실제 요구사항·서비스 동작·subagent 호출
- 다음: 프로젝트 확인과 첫 작업 계획

## 작업별 설명 양식
### 작업 이름 / 작업번호(AI가 관리)
1. **해결하려던 문제:** 사용자에게 어떤 불편·위험이 있었는가?
2. **구현한 동작:** 입력 → 처리 → 저장 → 화면 순서로 무엇이 일어나는가?
3. **선택 이유:** 왜 이 방법을 골랐으며 어떤 대안을 비교했는가?
4. **책임의 위치:** 어떤 모듈·함수가 어떤 규칙을 책임지는가?
5. **실제 확인:** 누가 어떤 방법으로 무엇을 기대하고 관찰했는가? VERIFY의 어떤 확인 기록과 연결되는가? AI의 내부 HTTP 응답 확인과 사용자의 실제 화면·버튼 확인을 구분한다.
6. **장애와 한계:** 어디서 이상을 발견하고 어떻게 대응하며 아직 무엇을 모르는가? 미검증 부분의 영향과 다음 확인 방법도 적는다.
7. **관련 근거:** 코드 위치·PLAN의 해당 선택 설명·VERIFY의 확인 기록.

### 쉬운 용어 풀이
- 용어 / 쉬운 뜻 / 이 기능에서의 예
- PLAN은 앞으로 할 일과 중요한 선택의 이유를 적는 문서이고, VERIFY는 실제로 확인한 방법과 결과를 적는 문서입니다.
- 선택번호는 중요한 선택에 붙인 표시입니다. 이런 번호는 AI가 문서의 관련 내용을 연결하려고 관리하며, 사용자가 직접 번호를 붙이거나 외울 필요는 없습니다.

### 설계 변경 이력
- 이전 선택 → 현재 선택 / 변경한 근거

## 최종 설명·제출 요약 양식

기존 프로젝트에 제출 양식과 필수 파일명이 있으면 그 양식에 아래 네 항목을 통합합니다. 별도 제출 파일을 임의로 늘리지 않습니다. 실제 작업 후 근거를 확인해 채우며, 아래 빈 양식은 선택이나 검증을 완료했다는 뜻이 아닙니다.

| 항목 | 짧게 답할 내용 | 연결할 근거 |
|---|---|---|
| 선택한 판단 | 어떤 문제에 어떤 방법을 선택했고 범위를 어디까지 정했는가? | SPEC의 관련 요구사항, PLAN의 해당 선택 설명 |
| 판단 근거 | 요구사항·데이터·제약 중 무엇을 근거로 삼았고 대안과 어떤 차이가 있었는가? | PLAN의 선택 이유·대안, 실제 코드·설정 위치 |
| 검증 결과 | 누가 무엇을 실행·조작했고 기대값과 관찰값은 각각 무엇이었는가? | VERIFY의 확인 기록과 실제 명령·출력·조작 기록 |
| 남은 한계 | 미구현·미검증·환경 제약은 무엇이며 결과에 어떤 영향을 주고 다음에 어떻게 확인할 것인가? | VERIFY의 미확인 항목, PLAN의 다음 작업 |

기존 기록을 통째로 복사하지 않고 핵심 판단과 근거 위치를 연결합니다. 예상 결과를 관찰 결과로 쓰거나, AI의 내부 응답 확인만으로 사용자 화면 확인까지 완료했다고 쓰지 않습니다. 확인하지 못한 항목은 미확인으로 표시하고 그 영향과 확인 방법을 남깁니다.
