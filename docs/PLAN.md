# 구현 계획과 선택 이유

SPEC의 요구사항을 구현하기 위한 기술·구조·알고리즘과 작업 순서를 정합니다. 요구사항 자체를 바꿔야 한다면 SPEC부터 갱신하고 변경 근거를 연결합니다. 실제 검사 결과는 VERIFY에 기록합니다.

상태: 미착수. 선택 이유는 실제 결정 시 기록합니다.

|---|---|---|---|---|

## 설계 결정

여기서 ‘선택번호’는 중요한 선택에 붙이는 표시입니다. 예를 들어 `D-01`은 ‘첫 번째로 기록한 선택’이라는 뜻입니다. AI가 선택 이유와 확인 결과를 연결하려고 관리하므로 사용자가 직접 번호를 붙이거나 외울 필요는 없습니다.

| 선택번호 | 선택한 판단 | 선택 이유·비교 대안 | 판단 근거 | 확인 기록·상태 | 한계·영향·변경 조건 | 관련 코드 |
|---|---|---|---|---|---|---|
| D-01 | 미정 | 미정 | 미확인 | 미실행 | 미확인 | 미구현 |

판단 근거에는 관련 요구사항, 제공 데이터에서 확인한 사실, 자원·시간 조건, 실제 비교 결과 또는 공식 자료의 위치를 적습니다. AI의 제안과 사용자가 확정한 선택을 구분합니다. 근거가 부족하면 가정과 확인할 항목을 남깁니다. 실제로 실행한 확인 방법과 결과는 VERIFY에 기록하고, 해당 확인 기록의 번호나 위치를 연결합니다.

## 운영 방식과 시간 예산

- 방식: 미정 (단독 진행 / 역할을 나눠 진행 / 독립 작업 병렬 진행)
- 선택 이유: 미정 (규모·남은 시간·도구 지원·독립 검증 필요성·인계와 통합 비용)
- 전체 마감 / 과제 작업 제한 / 후속 절차에 남길 시간: 미확인
- 현재 시각·남은 시간: 미확인
- 요구사항·계획 / 구현 / 검증·수정 / 문서 / 제출 예산: 미정
- 필수 기능 우선순위 / 뒤로 미룰 선택 기능: 미정
- 다음 점검 시점·시간 부족 시 축소할 범위: 미정

[시간 관리 안내](../references/TIME_MANAGEMENT.md)의 예시는 실제 제한에 맞춰 조정합니다. 응답 대기·인계·통합도 예산에 포함합니다. 번호와 시간 기록은 AI가 관리합니다.
