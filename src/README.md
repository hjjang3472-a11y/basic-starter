# 코드 폴더 안내

`src/`는 서비스가 동작하도록 만드는 코드를 둘 수 있는 공간입니다. 현재는 안내 파일만 있으며 실제 서비스 코드는 아직 없습니다.

기존 프로젝트에 `app/`, `backend/`, `frontend/` 등의 코드 폴더가 있다면 그 구조를 그대로 사용합니다. 설명도 실제 코드가 있는 폴더의 README에 작성합니다. 이 양식을 사용하려고 `src/`를 새로 만들거나 기존 코드를 옮길 필요는 없습니다.

## 현재 파일과 역할

경로는 프로젝트 루트를 기준으로 적었습니다. 현재 실제로 존재하는 파일만 나열합니다.

| 경로 | 역할 | 핵심 처리 | 연결되는 파일 |
|---|---|---|---|
| `src/README.md` | 코드 폴더의 파일과 동작을 설명하는 안내 | 코드 파일이 늘어나면 목록과 연결 관계를 갱신합니다. 서비스 실행 기능은 없습니다. | 실제 실행 정보는 루트 `RUN.md`에 기록합니다. |
| `src/.gitkeep` | Git에 이 폴더를 남기기 위한 자리 표시 | 실행되는 처리는 없습니다. | 없음 |

## 구현하면서 갱신하는 방법

- 구현 담당은 할당된 파일을 추가·변경·삭제한 작업 단위가 끝날 때 이 목록도 함께 갱신합니다.
- 파일마다 무엇을 하는지, 어떤 입력을 받아 어떤 처리를 하는지, 어느 파일과 연결되는지 쉬운 말로 설명합니다.
- 파일을 삭제하거나 이름·위치를 바꾸면 예전 목록과 연결 관계도 수정합니다.
- 아직 만들지 않은 파일과 계획한 기능을 실제 구현된 것처럼 적지 않습니다. 계획은 `docs/PLAN.md` 역할의 문서에 남깁니다.
- 파일이 많아지면 기능별로 묶고 하위 폴더 README에 연결할 수 있습니다. 실제 구조와 일치하도록 유지합니다.
- 실행 명령은 `RUN.md`, 검증 결과는 `docs/VERIFY.md` 역할의 문서에 기록하고 여기서는 필요한 위치만 연결합니다.
- 기존 README가 있으면 내용을 보존하면서 필요한 설명을 보완합니다. 다른 담당과 같은 README를 동시에 수정하지 않습니다.
